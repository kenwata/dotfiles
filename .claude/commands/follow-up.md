このセッションで **計画したことが全部やられたか** を検査し、漏れを是正してから終了してください。主軸は計画の完遂であり、情報の保存は従です。要点:

1. **前提確認とモード判定**: git リポジトリか・`HANDOFF.md` があるかを確認し、次の3モードのいずれかを判定して **報告に明記する**。検査の中核(手順2・4・7)はどのモードでも必ず実行する — 縮退させるのは着地物に依存する段(手順3の②③④⑦・手順5の持ち越し先・手順6)だけである。
   - **四層モード**: `HANDOFF.md` あり。全手順を実行。
   - **単発(git)モード**: `HANDOFF.md` 無し・git リポジトリ。手順3の②③④⑦と手順6をスキップし、手順5の判断待ちは AskUserQuestion でその場で決着させる。
   - **単発(非git)モード**: `HANDOFF.md` 無し・非 git。単発(git)モードに加え、手順2・3・4の対象特定を会話・ファイル現物ベースへ切り替える。
2. **照合の基準とセッション範囲の確定**: 基準は優先順に ①`docs/design/<slug>.md`(`/breakdown` が落とした承認済みプランの永続版)②`TODO.md` の該当タスクの完了条件 ③プランファイル(`~/.claude/plans/`。**今まさに承認された最新1本のみ**。同一セッション内で plan mode を複数回通ると上書きされるため、先の計画は①②で照合するほかない)。①②が無い場合のみ③単独へ、③が無い場合は①②へフォールバックする。**③の特定は plan mode 突入時にセッションへ提示されたパスを使う**(`ls -t ~/.claude/plans` で最新を推測しない — 並行セッションがあると最新が自分のものとは限らない)。**plan mode を一度も通っていない回は、会話中のユーザー指示と自分が宣言した実施項目を基準にし、基準が会話にしかないことを報告に明記する**。範囲はセッション開始時の HEAD から現在まで(未コミット変更を含む)。**非 git では「このセッションで自分が Write/Edit したファイルのパス一覧」を範囲とする**。**起点が不明なときは推測せずユーザーに確認する**。
3. **機械チェック**(結果を一覧で示す): ①更新したつもりで書けていないものの検出 — 宣言ではなく実体で確認する(git なら `git diff`、非 git なら対象ファイルを Read して現物確認する)②行数予算(各ファイル冒頭の規約コメントが優先)(**四層モードのみ**)③`HANDOFF.md` の「要確認」の各行が既に解消していないか(**四層モードのみ**)④`TODO.md` の `[x]` と `HANDOFF.md` の完了記述の突合(**四層モードのみ**)⑤着地物内の `/tmp`・スクラッチパッドのパス ⑥完了条件の数値の再計測(**再実行可能な計測コマンドが完了条件に記録されているタスクに限る**。それ以外は手順4へ回す)⑦**構造ドリフト検査**(**四層モードのみ**。`docs/architecture.md` がある場合のみ): `git ls-files | sed -e 's|/[^/]*$||' -e 't skip' -e 's|.*|.|' -e ':skip' | sort -u` で追跡対象ディレクトリを洗い出し `docs/architecture.md` のツリーと突合して未記載を検出、`git ls-files | grep -E '\.(py|ts|tsx|js|jsx|mjs|cjs|rs|go|java|scala|rb|hs|sc)$' | sed -e 's|/[^/]*$||' -e 't skip' -e 's|.*|.|' -e ':skip' | sort | uniq -c | awk '$1>5'` で `coding-principles.md` §13 のフラット禁止(5個)への違反候補を検出する(macOS の BSD sed でも動く、`;` 区切りではなくラベル付き分岐の形)。**出力は候補であり、実装ファイルかどうかを見て判定する**(`docs/` の markdown やマイグレーションを機械的に違反扱いしない)。
4. **サブエージェント検査**(セルフチェックは自分の盲点を継承するため、必ずコンテキストの外へ出す。**どのモードでも必須**): 1本起動し、**渡す入力を次に固定する** — 手順2で確定した基準の原文 / git ならセッションの `git log` と `git diff`(複数リポジトリにまたがるならその全て)、非 git なら**このセッションで自分が Write/Edit したファイルのパス一覧**(パスは事実なので渡してよいが、判断・スコープ解釈は渡さない。中身はサブエージェント自身に Read させる)/ 四層モードのみ `HANDOFF.md` の更新案と変更したファイルの現物。**会話履歴と自分の判断・スコープ解釈の要約は渡さない**(「これは意図的にスコープ外にした」という自己弁護が混ざると照合が甘くなる)。**既知の限界**: 非 git では、触ったことを自分が忘れているファイルは検査に乗らない。git repo では `git status`(未追跡含む)がこの穴を塞ぐ。検査させるのは (a)計画が挙げた変更対象が diff(非 git ならパス一覧)に現れているか — 現れないものは「未着手」か「不要と判断した」かを区別 (b)計画の検証項目を実行したか (c)完了条件の各項目に証跡があるか (d)計画に無いのに実施したもの(逆方向の検査)(e)着地物だけで次の一手に着手できるか(**四層モードのみ**)(f)diff に現れる情報のうち着地物へ未反映のもの(**四層モードのみ**)(g)`docs/decisions.md` に撤回の記録があるとき参照先文書に旧記述が残っていないか(**四層モードのみ**)。**返ってきた指摘は是正の前に実測で精査する** — fresh-context は盲点を消す代わりに会話で確立した計測手法も失っており、前例では11件中1件が取り違えだった。なお「ユーザーから修正指摘を受けた回に規約側(`CLAUDE.md` / `.claude/rules/` / auto memory)の差分がゼロで終わっていないか」は **自分で判定する** — 指摘の有無は会話にしかない情報で、上の入力定義と矛盾するため出せない。
5. **是正**: 着地物への追記・整形・ポインタの補完は **自動で直す**(⑦の検出で `docs/architecture.md` にツリーの追記漏れがあった場合も含む)。新しいユーザー決定を要するもの・タスクの再解釈・スコープの変更は **報告に留めてユーザー判断を仰ぐ**(⑦で検出したフラット違反候補の是正としてファイルを移動する判断もここに含まれる — 移動は影響が大きいため自動では行わない)。ただし回す前に、その論点が完了条件・`docs/decisions.md`・設計文書で **既に決着していないかを実測で確かめる** — 語の一致だけを見て母集合を取り違えると、成立しない問いをユーザーへ投げることになる。**ユーザー判断へ回すものは、報告に書くだけで終わらせない** — 四層モードでは `HANDOFF.md` の「要確認」へ必ず載せる(いま決めなくてよいものには「急がない」と添える)。**単発モードには持ち越し先が無いため、AskUserQuestion でその場で決着させる**(保留という選択肢を作らない — report-only にすると、HANDOFF への転記義務を追加した 2026-08-20 の失敗を単発モードで再導入することになる)。報告はセッションと共に流れ、着地物だけが次セッションへ渡る — 四層モードでは手順6の終了手順は手順5とは別の段なので、回した論点が自動では引き継がれない(2026-08-20 に実際に落ちた)。
6. **既存の終了手順を実行**(**四層モードのみ**。`HANDOFF.md` が無い場合はスキップし、その旨を報告する): 規定は `~/.claude/templates/BLUEPRINT.md` §6 が正(**ここに転記しない**。2箇所に置くとドリフトする)。
7. **報告の前に advisor**(**どのモードでも必須**): 完了判断そのものを外部レビューにかける。ここを飛ばすと、漏れチェックの結果自体が無検査で通る(2026-08-20 に実際に起きた失敗がこれである)。
8. **報告**: 検出件数・是正した内容・ユーザー判断へ回すものを簡潔に示す。

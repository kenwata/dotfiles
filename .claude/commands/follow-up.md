このセッションで **計画したことが全部やられたか** を検査し、漏れを是正してから終了してください。主軸は計画の完遂であり、情報の保存は従です。要点:

1. **前提確認**: git リポジトリであること・`HANDOFF.md` の存在を確認する。無ければ手順3の機械チェックのみへ縮退し、縮退した旨を報告に明記する。
2. **照合の基準とセッション範囲の確定**: 基準は優先順に ①`docs/design/<slug>.md`(`/breakdown` が落とした承認済みプランの永続版)②`TODO.md` の該当タスクの完了条件 ③プランファイル(`~/.claude/plans/`。**今まさに承認された最新1本のみ**。同一セッション内で plan mode を複数回通ると上書きされるため、先の計画は①②で照合するほかない)。①②が無い場合のみ③単独へ、③が無い場合は①②へフォールバックする。範囲はセッション開始時の HEAD から現在まで(未コミット変更を含む)。**起点が不明なときは推測せずユーザーに確認する**。
3. **機械チェック**(結果を一覧で示す): ①更新したつもりで書けていないものの検出 — 宣言ではなく `git diff` の実体で確認 ②行数予算(各ファイル冒頭の規約コメントが優先)③`HANDOFF.md` の「要確認」の各行が既に解消していないか ④`TODO.md` の `[x]` と `HANDOFF.md` の完了記述の突合 ⑤着地物内の `/tmp`・スクラッチパッドのパス ⑥完了条件の数値の再計測(**再実行可能な計測コマンドが完了条件に記録されているタスクに限る**。それ以外は手順4へ回す)。
4. **サブエージェント検査**(セルフチェックは自分の盲点を継承するため、必ずコンテキストの外へ出す): 1本起動し、**渡す入力を次に固定する** — 手順2で確定した基準の原文 / セッションの `git log` と `git diff`(複数リポジトリにまたがるならその全て)/ `HANDOFF.md` の更新案と変更したファイルの現物。**会話履歴と自分の判断・スコープ解釈の要約は渡さない**(「これは意図的にスコープ外にした」という自己弁護が混ざると照合が甘くなる)。検査させるのは (a)計画が挙げた変更対象が diff に現れているか — 現れないものは「未着手」か「不要と判断した」かを区別 (b)計画の検証項目を実行したか (c)完了条件の各項目に証跡があるか (d)計画に無いのに実施したもの(逆方向の検査)(e)着地物だけで次の一手に着手できるか (f)diff に現れる情報のうち着地物へ未反映のもの (g)`docs/decisions.md` に撤回の記録があるとき参照先文書に旧記述が残っていないか。**返ってきた指摘は是正の前に実測で精査する** — fresh-context は盲点を消す代わりに会話で確立した計測手法も失っており、前例では11件中1件が取り違えだった。なお「ユーザーから修正指摘を受けた回に規約側(`CLAUDE.md` / `.claude/rules/` / auto memory)の差分がゼロで終わっていないか」は **自分で判定する** — 指摘の有無は会話にしかない情報で、上の入力定義と矛盾するため出せない。
5. **是正**: 着地物への追記・整形・ポインタの補完は **自動で直す**。新しいユーザー決定を要するもの・タスクの再解釈・スコープの変更は **報告に留めてユーザー判断を仰ぐ**。
6. **既存の終了手順を実行**: 規定は `~/.claude/templates/BLUEPRINT.md` §6 が正(**ここに転記しない**。2箇所に置くとドリフトする)。
7. **報告の前に advisor**: 完了判断そのものを外部レビューにかける。ここを飛ばすと、漏れチェックの結果自体が無検査で通る(2026-08-20 に実際に起きた失敗がこれである)。
8. **報告**: 検出件数・是正した内容・ユーザー判断へ回すものを簡潔に示す。

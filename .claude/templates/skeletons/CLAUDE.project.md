- コーディング規約: `.claude/rules/` — path-scoped で該当ファイル操作時に自動適用される。規約の追加・編集もそこで行う

## セッション運用

- 開始時: `HANDOFF.md` を読み、「次セッションの最初の一手」から着手する(`TODO.md` があればそれも読む。`plan.md`(全体構想)は次の一手が `/elaborate` の時だけ読む。それ以外は読まない)
- 長時間の実行で途中終了を避けたい場合: 必要に応じて `/goal <検証可能な完了条件>, or stop after 20 turns` を補助的に使う
- plan mode 承認後: そのプランの成果が **既存のどの `T<n>` の完了条件で検証されるか** を判定する(正は `TODO.md` §0)。答えが有れば **タスク粒度** — `/elaborate`・`/breakdown` を起動せず、そのまま実装に進む。無ければ **計画粒度** — 実装に着手する **前に**、同一セッション内で `/elaborate`(設計書)→ `/breakdown`(`TODO.md`)を実行する(検討の行間が生きているのは承認直後だけ)
- 判断に迷ったら推測で進めず、`HANDOFF.md` の「要確認」に記録して依存しない次のタスクへ進む
- タスク完了ごとに git commit(1タスク=1コミット)。メッセージ: `<prefix>: 要約`(TODO 管理下なら要約に T<n> を含める)+ 本文に「タスク: 依頼内容」「対応: どう解決したか」。変更を生まないタスク(調査・見送り判断)も `git commit --allow-empty` で同書式のコミットを残す(調査結果の要点は「対応:」に書く)
- 過去の経緯調査: `git log --oneline -- <path>` → `git log --grep=<語>`(タスクIDは境界付き `-E --grep='T7([^0-9]|$)'` 形式で桁違いIDへの誤マッチを防ぐ)→ `git show <sha>` の順で絞り込む。`git log` の全件読み込みはしない
- 終了時: 未コミット変更を確認する。`HANDOFF.md` の最後に完了したタスク、仕掛かり中、次の一手、要確認のいずれかが変わった場合は全体上書きする。続けて毎回コールドスタート確認(`HANDOFF.md`(と `TODO.md`)だけで正しい最初の一手と必要な参照先が分かり、このセッションで棄却した経路を繰り返さないか)を行い、不足があれば `HANDOFF.md` 冒頭の規約に従って補う(過去の transcript は自動探索しない)。該当する判断を `docs/decisions.md` に追記し、TODOのローテーション規約を適用して終了処理の変更をコミットする。設計書全体の再照合や独立レビューは行わない
- 総点検: 最新 `Follow-Up-Checkpoint: true` 以後に完了した異なるT番号が5件に達した時、依存グループ完了時、統合前、ライブ検証前、設計変更または不整合を検出した時は、次のTへ進む前に `/follow-up` を実行する
- 修正指摘を受けたら: 直して終わりにしない。同種ミスが再発しうるか判定し、しうるなら規約化してから完了を報告する
  - 特定ファイルの書式(TODO・changelog 等) → そのファイル冒頭のコメント規約に追記
  - プロジェクト全体のコード規約 → `.claude/rules/`(paths: 付き)
  - 全プロジェクト共通の規約 → `~/.claude/templates/rules/` への還元を提案
  - エージェントの振る舞い(聞き方・判断の仕方・報告の仕方) → その瞬間に発火する hook の点検リスト(`~/.claude/hooks/check-stop-question.sh`・`check-question-legibility.sh`)。成果物の中身の規則は機械検査を最優先
  - 環境固有の事実 → プロジェクト内の該当文書。auto memory は発火しないため再発防止の手段に数えない

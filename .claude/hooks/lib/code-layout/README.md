# code-layout

`coding-principles.md` §14(Layout)の最低限を検査する CLI。`hooks/check-code-layout.sh`(PostToolUse の Write|Edit)から呼ばれ、指摘があれば stderr に一覧を出して exit 2 で Claude に差し戻す。ファイルは書き換えない。

整形ツールは行を折り返すが、空行は入れない。そのため、段落の抜けは整形ツールでは直らず、この検査で拾うしかない。検査するのは機械で決められる位置だけで、どこで段落を切るかという意味の判断は §9 の完了前点検に残す。

## 検査する位置

| kind | 位置 |
| --- | --- |
| `width` | 100 桁を超える行。全角文字は 2 桁で数える。URL を含む行、空白のない中身が 58 桁以上の文字列リテラル(ハッシュ・生成データ)を含む行、文字列リテラルだけの行は、折り返せないので除く。メソッドチェーンや引数の並びは折り返せるので除かない |
| `glued-block` | 閉じたブロックの直後に、空行なしで同じ深さの文が続く箇所。else・catch などの続きの節と、本体がジャンプ 1 文だけのガード節の連続は除く。オブジェクトリテラルや複数行の呼び出しの閉じはブロックとみなさない |
| `glued-return` | 2 文以上の直後に空行なしで続く閉じの `return`。1 行のガード節は数えない。暗黙の return の言語(Rust・Scala・Ruby・シェル・Haskell)では検査しない |
| `long-run` | 空行なしで 8 文以上続く箇所。コメント・import・要素の行(`,` で終わる)・複数行の式の続き・型やクラスのメンバー・JSX のマークアップ・1 行のガード節の連続(まとめて 1 文)は数えない |

構文木は作らない。整形後のテキストをインデントと数種類の記号で読むので、言語ごとの差分は `languages.mjs` の表(拡張子・コメント記号・閉じの見分け方)に閉じている。言語を足す時は表に 1 行加える。

## 適用範囲

- プロジェクトが `<rules-dir>/rules/coding-principles.md` を持つ時だけ動く。規約を配布していないリポジトリでは何もしない。`<rules-dir>` は既定で `.claude`。Codex のアダプター(`.codex/hooks/check-code-layout.mjs`)だけが `--rules-dir=.codex --rules-dir=.claude` を渡す
- Edit で `new_string` が空(削除だけ)の場合は何も返さない。削除した位置は保存後のファイルから特定できず、ファイル全体を対象にすると編集していない既存箇所の指摘が出るため
- 依存・生成物・テストデータのディレクトリ(`node_modules`・`dist`・`fixtures` など、`cli.mjs` の `SKIPPED_DIRECTORIES`)は除く
- Edit(部分編集)では、`new_string` の行に触れる指摘だけを返す。行の特定には `../markdown-format/scope.mjs` を使う

## 閾値の根拠(2026-09-24 に計測)

アクティブな 2 つのプロジェクトの既存コードに当てた結果。

| プロジェクト | 対象 | width | glued-block | glued-return | long-run |
| --- | --- | --- | --- | --- | --- |
| SpacialOchestrationResearch | `src/**/*.py` 107 ファイル・11,204 行 | 1 | 354 | 69 | 67 |
| VC_Analysis | `src/**/*.{ts,tsx}`(fixtures 除く)108 ファイル・20,819 行 | 1,684 | 261 | 101 | 94 |

`long-run` の閾値を 10 にすると SpacialOchestrationResearch の指摘は 67 件から 30 件に減る。ただし、8〜9 文の連続を抜き出して読むと、どれも手順の切り替わりが空行なしで続いていたので、8 のままにした。Edit では編集した行に触れる指摘だけを返すので、1 回の編集で出る件数は小さい。

計測で見つけた誤検出(union 型の続きの行、1 行のガード節の連続、interface や引数の型リテラルのメンバー、JSX のマークアップ、ヒアドキュメント、`echo ...; return` のシェルのガード節)は、`test/layout.test.mjs` の後半に回帰テストとして固定してある。差分レビューで再現した読み違い(Ruby の `<<` 追加演算子とシェルの `<<<`、通常の文字列の中のバッククォート、長いトークンを含む折り返せる行、`export default {`、削除だけの Edit)も同じく固定してある。

## 既知の限界

- Bash 経由のファイル変更では動かない(Write/Edit・apply_patch を通らない)
- Codex では、追加された行の塊がファイル内に 1 回だけ現れる時だけ検査する(`}` だけの行など、位置を特定できない塊は読み飛ばす)
- Edit の `new_string` が短いと、同じ文字列を含む別の行も編集した行とみなす(`../markdown-format/scope.mjs` の仕様)
- 構文木を作らないので、整形されていないコード(1 行に複数のブロック)では閉じを見落とす。整形ツールを通した後のコードが前提
- Haskell はブロックの閉じを判定しない(レイアウト規則が式の中にも及ぶため)
